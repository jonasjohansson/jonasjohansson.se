Website review — 7 September 2026

The strip wall, SeasonMix typography, warm neutral palette, and large project photographs give the site a recognisable identity. The most useful next work is to stabilise image loading and navigation, then make project discovery and contact easier.

This review covers a fresh local production build. I checked all 28 project routes at 390 × 844, and inspected the homepage plus Dome Dreaming, Jagad, Tufting ex Machina, NAVA, and Klättermusen at 390 × 844, 844 × 390, 1440 × 900, and 1920 × 1080. I inspected screenshots in light and dark themes, exercised keyboard navigation, simulated failed and delayed requests, and compared direct navigation with client-side navigation under reduced motion. Browser checks used Chrome, including emulated touch; physical iOS/Safari and the deployed site's delivery configuration were outside this review.

`npm run build` passed. The generated site has 37 HTML documents, including redirects. A scan found no missing local paths referenced by HTML links, images, srcsets, stylesheets, or scripts. Routine page visits produced no uncaught JavaScript errors. The JS bundle is 8.62 kB gzipped and CSS is 5.16 kB gzipped; media is the larger performance opportunity.

The following fixes are ordered by impact. P1 means a significant browsing defect; P2 means a functional, accessibility, or delivery improvement.

1. **P1 — Reserve image-row space before images load.** In a fresh Dome Dreaming load, 20 of 24 images initially measured 0 × 0. This happened at all four viewport sizes. They appear as scrolling triggers lazy loading, but their arrival expands the document: desktop height grew from 8,236 to 15,046 px. The initial blank regions are a loading/layout problem, not permanently missing files. The row's automatic width and margins, combined with zero flex basis on children, leave its size dependent on decoded image content. See [project.css](../../src/css/modules/project.css), lines 295–320 and 387–391. Give `.media-row` a definite width, preserving its existing maximum width; on mobile, explicitly stretch its children and reset their flex sizing. A browser-only preview using the CSS below reserved every row's dimensions even with image requests blocked. Keep this fix covered by a check that inspects geometry before image delivery. Reserving space before loading is also the approach recommended in [web.dev's layout-shift guidance](https://web.dev/articles/optimize-cls#images_without_dimensions).

   ```css
   .media-row { width: 100%; }

   @media (max-width: 768px) {
     .media-row { align-items: stretch; }
     .media-row > .media-item,
     .media-row > .media-item:not(.hero):not(:first-child) {
       flex: none;
       width: 100%;
     }
   }
   ```

2. **P1 — Make navigation ignore stale responses and recover from failure.** Delay the Firestarter request, open it, and press Back before it completes: the URL becomes `/`, but the late response inserts Firestarter underneath the homepage introduction. Aborting the request instead leaves `/firestarter/` in the address bar with no project content and no visible error. [router.js](../../src/js/router.js), lines 47–63 and 123–247, commits route state before fetching and never checks whether that request is still current. Use a navigation generation/token plus cancellation, validate the fetched section before committing it, and provide a retry or normal-navigation fallback. Announce success after the content has actually arrived. Test Back during a delayed request and a failed request.

3. **P1 — Keep touch navigation usable in landscape.** At 844 × 390, the homepage becomes 28 vertical strips roughly 29 px wide. Their labels disappear; hover expansion is disabled on touch devices, and a tap immediately opens the project. Visitors cannot identify the destination before choosing it. The labelled row layout is gated on both touch and portrait orientation in [strips.css](../../src/css/modules/strips.css), lines 169–226. Apply a labelled list or card presentation across touch orientations, with a width-based fallback for narrow windows. [Screenshot](../../screenshots/2026-09-07-review/landscape-wall.png).

4. **P2 — Move keyboard focus into the opened project.** Activating a strip with Enter hides the focused anchor without focusing the inserted content. In the reproduced sequence, the next Tab went to Labs in the footer and jumped past the entire project. The live announcement does not repair focus order. Focus the new heading or main region after successful navigation and restore focus to the originating strip when returning. Also put the homepage introduction and project collection inside its main landmark: [the layout](../../_includes/layouts/jonasjohansson.njk), lines 30–49, currently leaves the homepage's `<main>` empty, so “Skip to content” targets an empty region. A homepage-to-project transition also leaves the homepage H1 in the document alongside the project H1.

5. **P2 — Apply motion preferences whenever project content is mounted.** With reduced motion enabled, directly visiting Jagad pauses its videos, but opening Jagad from the homepage starts playback when the first video enters view. [main.js](../../src/js/main.js), lines 137–143, runs the preference check only at initial startup; [project.njk](../../project.njk), lines 55–63, supplies autoplay again in fetched content. Share a media-initialisation function between both paths and handle preference changes. Add a play/pause affordance: videos currently have no controls, including when reduced motion leaves them paused.

6. **P2 — Preserve project titles and update metadata after navigation.** All checked project tabs become “Jonas Johansson” after JavaScript initialises. [strips.js](../../src/js/strips.js), lines 260 and 310, overwrites the useful title emitted by the metadata template. After opening Dome Dreaming from home, the canonical remains the homepage URL; the rest of the head is also inherited. Use “Dome Dreaming — Jonas Johansson” and update the relevant description/canonical/social metadata when the route changes. The server-generated project metadata is already present; reuse it. This is a browser-state inconsistency, not evidence that direct project pages are absent from search indexes.

7. **P2 — Keep media requests proportional to what is visible.** The desktop and landscape homepages each requested 28 AVIF strip images, totalling about 5.30 MB. The mobile homepage initially loaded five backgrounds; opening one project immediately assigned all 28 backgrounds, although the navigation wall was below the project. [router.js](../../src/js/router.js), lines 138–147, bypasses the existing intersection observer. Keep that observer active across navigation. Generate smaller strip candidates instead of the single 1920 px width in [eleventy.config.js](../../eleventy.config.js), and upgrade the active preview when needed. Pass accurate `sizes` values to project images in multi-image rows; all current shortcode calls default to `100vw`. Use full-quality imagery where visitors are actually inspecting the work.

8. **P2 — Describe the artwork that carries information.** All 163 generated project images have `alt=""`, and project videos are all marked `aria-hidden="true"`. The build deliberately defaults images to decorative in [eleventy.config.js](../../eleventy.config.js), lines 488–498. For a visual portfolio, identify the key images whose composition, material, scale, or interaction adds information beyond the prose, and author concise descriptions for those. Keep empty alternatives for redundant views and purely decorative imagery. This distinction follows [W3C's informative-image guidance](https://www.w3.org/WAI/tutorials/images/informative/); the count alone does not establish that every image needs an alternative.

9. **P2 — Include project templates in deployment triggers.** The push path filter in [deploy.yml](../../.github/workflows/deploy.yml), lines 6–22, omits `project.njk`, `redirect.njk`, and `scripts/**`. A commit changing only project markup therefore does not trigger deployment. Include the actual build inputs or remove the restrictive path filter. This finding comes directly from the workflow configuration; no deployment was initiated.

10. **P2 — Give the server-rendered site a complete fallback.** With JavaScript disabled, all 28 desktop strip backgrounds are empty and their labels remain hidden, leaving an invisible navigation wall. Direct project pages show the homepage biography first and have no visible header. Render route attributes in the template, render usable images and labels in HTML, and enhance their appearance with JavaScript. See [strips.njk](../../_includes/components/strips.njk), [header.njk](../../_includes/components/header.njk), and [route-init.njk](../../_includes/components/route-init.njk). [Homepage without JavaScript](../../screenshots/2026-09-07-review/no-js-home.png).

The design changes below are recommendations based on the rendered pages, rather than functional failures.

| Opportunity | Recommended change |
| --- | --- |
| The biography dominates the opening screen. At 390 px, work starts around y=490. At 1440 px, the introduction runs almost edge to edge. | Lead with a short statement about the work, followed by visible “Projects”, “About/CV”, and “Email” links. Keep the longer biography available below or behind About. Give introductory prose a stable reading width instead of the abrupt width change at 1440 px. |
| The expressive wall is difficult to scan for a particular project. Its order changes on every home reload, and desktop names appear only on hover. | Keep the wall as the visual signature, add a compact labelled index or list view, and use a curated or stable default order with an optional shuffle. Expose existing categories only if they help people find work. |
| Contact and CV sit below the complete wall. On mobile the footer begins around y=4,601, after 28 finished projects and eight placeholders. | Repeat Email and CV near the introduction. Present upcoming work as a compact note or disclosure so it does not add eight rows before contact. |
| A project title doubles as the home link without a visible navigation cue, and disappears from the viewport while reading. | Give projects an explicit “All projects” link, plus a next-project choice at the end. Preserve the current place in the collection when returning. Browser Back restored the mobile scroll position in my check; retain that behaviour. |
| Every project hero occupies a full viewport and uses a centred cover crop. | Add per-project focal points and optional mobile hero images. Let artwork that needs its complete composition use a shorter or uncropped hero. At 390 × 844, a 16:9 source retains only about 26% of its horizontal field in this cover box. The mobile hero also begins 32 px below the top because the mobile bleed variable changes the inherited negative top margin; correct that if full bleed is intended. |
| Opening statements and body copy use different centred left edges; large-screen body measure increases from 65ch to 80ch. | Choose a shared text alignment and hold body measure roughly constant. Keep large opening statements distinct through size and spacing. Preserve the existing equal-height image pairs once their loading geometry is fixed. |
| Theme and sound behaviour are implicit. The theme follows the clock, and touch clicks can trigger melody notes anywhere on the homepage. | Offer small theme and sound controls, remember the selection, and default sound to an explicit opt-in. Respect the system colour preference unless the visitor chooses otherwise. |

There are also useful maintenance improvements:

- **Separate the image cache from the published artifact.** The local output is about 435 MB. Approximately 169 MB consists of image-cache files not referenced by the current generated HTML. CI restores `dist/img` and uploads the whole `dist` directory, so obsolete variants can accumulate in deploy artifacts. Retain the reusable cache, but publish assets from a current build manifest.
- **Invalidate Open Graph crops when their sources change.** `processOgImage()` names files by slug and skips work whenever the destination already exists. Since that directory survives builds and is restored in CI, changing a hero does not necessarily regenerate its sharing image. Include a content hash or compare the source with the cached output.
- **Report malformed project data.** Several metadata and image-processing paths swallow errors. The responsive-image fallback returns a raw project-image path even though raw images are deliberately excluded from deployment. Fail the build with the project slug and field when required content is invalid, or return an intentional placeholder.
- **Remove inactive interaction infrastructure.** No filter controls are rendered, but the filter UI machinery remains. `setStripsHeight()` is empty but still has resize, scroll, and orientation handlers. `resetProjectColors()` clears unused variables. Keep the visible-count logic needed by sound, remove unused branches, and keep project colour data in one source.
- **Make visual verification cover loading and navigation.** The existing screenshot script covers only home and Dome Dreaming and does not exercise client-side navigation. Add a small smoke check for pre-load row geometry, delayed navigation followed by Back, keyboard focus, reduced-motion navigation, and landscape touch labels. Those checks directly cover the reproduced defects.
